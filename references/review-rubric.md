# 评审标准与评分锚点

## 五个维度

审稿意见必须落到这五个维度上，避免「感觉不太行」这类无法回应的评价。

### 1. 贡献与新颖性（Contribution / Novelty）

问的是：**这篇论文让读者知道了什么此前不知道的事？**

| 分 | 锚点 |
| --- | --- |
| 5 | 提出新问题，或对已知问题给出反直觉且被证据支撑的答案；后续工作会引用它来支撑前提 |
| 4 | 已有方向上明确的推进：新方法/新场景/新证据，差异可一句话说清 |
| 3 | 增量工作，组合已有技术解决具体场景，价值限于该场景 |
| 2 | 与已有工作差异微弱，或差异未被论证 |
| 1 | 重复已知结论，或贡献仅在实现层面 |

判断技巧：把作者的贡献句抽出来，问「如果这篇不存在，领域会损失什么」。答不上来就是 2 分以下。

### 2. 方法严谨性（Rigor）

问的是：**做法能不能支撑结论？**

| 分 | 锚点 |
| --- | --- |
| 5 | 设计、对照、分析三者闭合，替代解释被显式排除 |
| 4 | 主要威胁已被识别并处理，个别次要威胁留有讨论 |
| 3 | 方法合理但有 1–2 处未处理的明显混淆因素 |
| 2 | 存在能直接推翻结论的设计缺陷（无对照、样本偏差、指标与构念脱节） |
| 1 | 方法不可复现或与分析目标不匹配 |

### 3. 证据充分性（Evidence / Evaluation）

问的是：**结论的每句话都有对应的数据吗？**

| 分 | 锚点 |
| --- | --- |
| 5 | 结论强度与证据强度匹配；阴性结果、失败案例、边界条件都有报告 |
| 4 | 主结论有充分证据，个别断言略强于数据 |
| 3 | 主结论成立但缺少关键分析（如效应量、置信区间、消融） |
| 2 | 结论明显超出数据所能支撑的范围 |
| 1 | 无有效证据，或证据与结论无关 |

### 4. 影响力（Impact / Significance）

问的是：**谁会用它，用来做什么？**

| 分 | 锚点 |
| --- | --- |
| 5 | 改变领域内其他人的做法或提问方式 |
| 4 | 对特定子社区有明确价值，方法可被直接复用 |
| 3 | 对相邻工作有参考价值 |
| 2 | 价值限于作者自身项目 |
| 1 | 无可识别受众 |

### 5. 表达与呈现（Presentation）

问的是：**能不能顺畅读懂并复现？**

| 分 | 锚点 |
| --- | --- |
| 5 | 结构清晰，图表自解释，方法细节足以复现 |
| 4 | 可读性好，个别段落需要重读 |
| 3 | 能读懂但费力：术语不一致、长句多、图表缺标注 |
| 2 | 多处需要猜测作者意图 |
| 1 | 无法理解核心内容 |

## 总体建议的映射

不要独立给总体分，从五维推：

- 任一维 ≤ 2，且属于方法/证据 → **拒稿**（写作问题不构成拒稿理由，除非已无法理解内容）
- 贡献 ≥ 4、严谨 ≥ 3、其余 ≥ 3 → **小修**
- 贡献 ≥ 3、严谨 ≥ 3，但证据或表达有明显缺口 → **大修**
- 全部 ≥ 4 → **接受**

置信度单独给 1–5，并说明依据（是否熟悉该子领域、是否读过引用的近邻工作）。

## 常见拒稿理由（按出现频率）

1. **贡献增量** —— 与最近邻工作的差异只用一句话带过，没有对照实验或论证。
2. **结论超出证据** —— 30 人单校研究，却写成普适设计原则。
3. **缺少对照** —— 只有实验组，或基线是自己实现的弱版本。
4. **指标与构念脱节** —— 用点击率证明「理解加深」，用字数证明「反思质量」。
5. **相关工作缺失关键近邻** —— 尤其漏掉同一年同一会议的在投工作。
6. **不可复现** —— 超参、数据划分、提示词、模型版本未报告。
7. **伦理与声明缺失** —— 人类被试无 IRB，生成式 AI 使用未披露。
8. **写作层面** —— 贡献藏在第三页，摘要与结论不一致。

写意见时优先检查这 8 条，命中率高。

## 各会议口径差异

| 口径 | 特点 |
| --- | --- |
| CHI / CSCW | 重贡献多样性与方法反思；访谈/田野研究不要求统计显著，但要求样本合理性与反思深度；双盲严格，匿名泄露直接退稿 |
| NeurIPS / ICML | 重理论保证与实验规模；要求消融、方差、统计检验；rebuttal 期间可补实验 |
| TOCHI / IJHCS（期刊） | 要求完整文献综述与更长的讨论；一轮修改通常 6–12 个月 |
| 学位论文 | 额外要求完整文献综述、方法章的教学性、贡献的独立说明 |

## 审稿意见的写法

每条意见按 **现象 → 影响 → 建议** 三段：

```
现象：表 2 报告了 12.4% 的提升，但未给置信区间，也未说明 n。
影响：无法判断该提升是否超过个体差异带来的波动，主结论因此不成立。
建议：补报告 95% CI 与效应量；若样本量不足，请把结论改为「趋势性观察」。
```

三条禁忌：

- 不要写「这个实验不够充分」——作者不知道要补什么。
- 不要把多个问题塞进一条——作者回应时会漏。
- 不要人身评价——评论文本，不评作者。

## 输出模板（review 模式）

```markdown
## 评审摘要
（3–5 句：论文做了什么、用的什么方法、我的总体判断）

## 优点
（2–4 条，每条指向具体位置，不要空泛表扬）

## 主要问题
（按严重度降序，每条：现象 → 影响 → 建议）

## 次要问题
（措辞、图表、引用格式等，可用列表）

## 给作者的问题
（2–4 个能澄清关键疑点的提问，不给答案）

## 评分
| 维度 | 分数 | 理由 |
| --- | --- | --- |
| 贡献与新颖性 | /5 | |
| 方法严谨性 | /5 | |
| 证据充分性 | /5 | |
| 影响力 | /5 | |
| 表达与呈现 | /5 | |

**总体建议**：接受 / 小修 / 大修 / 拒稿
**置信度**：/5（说明是否熟悉该子领域）
```
